## 1. 검증할 가설

인터뷰 후 각 가설을 맞았다/틀렸다/모르겠다로 판정한다(§6 기록 양식).

| # | 가설 | 틀렸을 때의 의미 |
|---|------|----------------|
| H1 | 장애 대응에서 가장 오래 걸리는 건 "복구 실행"이 아니라 "원인 파악"이다 | 이 도구가 돕는 지점이 실제 병목이 아님 |
| H2 | 복구 명령 실행 전 사람의 승인은 "당연히 필요한 것"으로 받아들여진다 | 인간 승인 설계가 차별점이 아니라 마찰일 수 있음(소규모 세그먼트 반응) |
| H3 | 로그를 외부로 못 보내는 클라이언트(금융 등)에게 셀프호스팅 도구 니즈가 있다 | 셀프호스팅 포지셔닝 근거가 약해짐 |

## 2. 질문 흐름

### ① 아이스브레이킹 + 현황 파악 (2~3분)

- "요즘 맡으시는 프로젝트들, 장애 대응이나 모니터링은 보통 어떻게 하세요?
  클라이언트가 직접 갖추고 있나요, 아니면 대표님 쪽에서 세팅해주시나요?"

### ② Pain point 확인 (3~4분) — H1

- "장애 났을 때 새벽에 콜 받는 일 있으세요? 그럴 때 가장 답답한 지점이
  뭔가요?"
  - 답이 추상적이면: **"가장 최근에 있었던 장애 하나를 처음부터 끝까지
    얘기해 주실 수 있을까요?"** — 실제 겪은 일을 들어야 신호가 정확하다.
  - **"원인 파악"이 오래 걸리는지, "복구 실행"이 오래 걸리는지 구분해서
    듣는다** — 이 프로젝트는 전자를 돕는 도구다.
- "지금 쓰시는 모니터링/알림 도구 있으세요? (Datadog, New Relic, 아니면
  자체 스크립트?) 그거 쓰시면서 아쉬운 점 있으신가요?"

### ③ 포지셔닝 반응 확인 (5~6분) — H2, H3

원페이저를 읽어드리거나 보여주지 않고, **구두로 짧게 설명하고 반응을 본다.**

- "제가 만드는 게 있는데, 로그 보고 장애 원인을 자동으로 진단해서 '이렇게
  고치면 됩니다'라고 제안하는 에이전트예요. 근데 실행은 사람이 승인해야만
  되게 만들었거든요. 이거 들으시면 어떤 생각 드세요?"
  - "왜 자동 실행 안 하냐" → 세그먼트 1(소규모)에 가까운 반응
  - "당연히 승인 있어야지" → 세그먼트 2/3(중견 SaaS/규제 산업) 감각
- "오픈소스로 셀프호스팅해서 쓸 수 있게 만들고 있는데, 이런 거 클라이언트한테
  제안하신다면 어떤 반응 나올 것 같으세요?"
- (자연스럽게) "혹시 클라이언트 중에 금융/뱅킹처럼 데이터를 외부로 못 보내는
  규제 있는 곳도 있으세요? 그런 데선 이런 셀프호스팅 도구에 대한 니즈가
  어떨지 감이 있으신가요?" — 세그먼트 3에 대한 간접 정보를 얻을 기회.

### ④ 구매/도입 의사결정 확인 (2~3분)

- "만약 이런 도구가 있다면, 대표님 입장에서 도입 여부를 결정하실 때 뭘 가장
  먼저 보실 것 같으세요?" (가격, 검증된 사례, 설치 난이도 등 — 실제 구매
  기준을 알려준다)
- "이런 걸 무료로 오픈소스로 푸는 것과, 유료 지원/호스팅 옵션을 얹는 것
  중에 뭐가 더 끌리실 것 같으세요?"

### ⑤ 마무리 — 소개 부탁 (1~2분)

- "혹시 이런 얘기 들으면 관심 있어 하실 만한 다른 분 있으실까요? 특히 SRE
  팀 있는 회사나 금융권 쪽 아시는 분 있으시면 소개해주실 수 있을까요?" —
  첫 인터뷰 대상이 다음 대상을 연결해주는 흐름이 가장 효율적이다.

## 3. 주의할 점

- **원페이저를 그대로 읽거나 보여주면서 "어때요?"라고 묻지 않는다.** 문서를
  먼저 보여주면 상대가 문서에 반응하는 것이지, 자기 문제의식에서 나온 반응이
  아니게 된다. 대화로 pain point를 먼저 끌어내고, 그 다음에 "그거 도와주는
  걸 만들고 있다"는 순서로 간다.
- **차별점(승인 게이트가 아니라 explainability 검증)은 먼저 꺼내지 않는다.**
  경쟁사 비교는 상대가 "Datadog이랑 뭐가 달라요?"라고 먼저 물을 때 답하는
  정도로 충분하다(§4).
- 출처가 확인되지 않은 "은행 68% DORA" 통계는 말하지 않는다
  ([competitive-research.md](competitive-research.md) §4 참고).

## 4. 예상 질문과 답변

상대가 먼저 물을 때만 답한다.

| 질문 | 답변 |
|------|------|
| "Datadog이랑 뭐가 달라요?" | 승인 기능 자체는 Datadog·New Relic에도 있어서 차별점이 아닙니다. 셀프호스팅이라는 점, 그리고 승인 화면에 뜨는 근거가 믿을 만한지 직접 검증하고 있다는 점이 다릅니다. |
| "LLM은 어디서 돌려요? 결국 외부로 나가는 것 아닌가요?" | 현재 기본값은 속도 때문에 외부 API(Groq)를 쓰고, 이 사실은 README에 명시했습니다. 로컬 모델(Ollama)만 쓰는 구성도 이미 가능하고, 이를 기본값으로 바꾸는 것이 다음 작업입니다. |
| "성능은 어느 정도인가요?" | 멀티에이전트 도입 후 end-to-end 성공률이 10%에서 34%로 올랐습니다. 아직 높은 수치가 아니어서, 그래서 사람의 승인이 안전장치로 필요하다고 봅니다. |
| "서버 여러 대도 되나요?" | 설정 구조는 다중 서버 기준으로 설계했고(`config/servers.yaml`), 현재는 인스턴스당 한 대씩 운영합니다. 동시 모니터링은 다음 단계입니다. |

도입 결정 기준(④):
